# Changelog — Project Baca

All notable changes are documented chronologically following [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- `make prod-migrate` and `make prod-migrate-status` apply and list migrations on the production stack through a one-off `migrate` service. Each migration file runs in one transaction with its `schema_migrations` row under an advisory lock: a file that fails halfway leaves nothing behind, and two runs at once apply each file once. `scripts/migrate.sh` talks to `MIGRATE_DATABASE_URL` when it is set; `make migrate-up` on the dev stack is unchanged.

### Changed
- The production compose runs the GHCR release images of `ROTARIA_VERSION` for server and worker (`make prod-pull`, no login while the packages are public), so a host can roll back to the previous version; `make prod-build` still builds them from the checkout. Redis keeps an append-only file, so a restart no longer drops recent sessions and refresh tokens; server and worker get 30 s to finish in-flight work on stop instead of 10 s; every service logs through Docker's rotating `local` driver. The bundled MinIO moves behind the `minio` profile. `.env.production.example` gains `ROTARIA_VERSION` and `CLOUDFLARE_TUNNEL_TOKEN`.
- Object storage moves to Cloudflare R2 with a token that may only read and write objects in `baca-epubs` and `baca-covers`: at boot the server lists one key of each bucket instead of creating it, and creates a bucket only when it is missing. With `APP_ENV=production` the server exits non-zero when a bucket does not answer (for example a wrong secret, logged with the bucket and HTTP status) instead of booting with uploads and covers broken. The worker signs storage requests for `S3_REGION`.
- A session ends at most 90 days after sign-in however often it is used (`SESSION_MAX_DAYS`): a refresh past it answers 401 and the app returns to the guest view, and a rotated refresh token never lives past that point. A session already older than 90 days ends at its first refresh after the upgrade.
- `/auth/refresh`, `/auth/logout` and `/auth/revoke-all` no longer share the 20-per-minute login bucket: each refresh token (or, for revoke-all, each account) gets 10 per minute under a 300-per-minute ceiling per client, so many readers behind one address refresh without 429.
- Each field in a validation error's `details` (including a wrong sign-up code, `otp_invalid`, and an overlong curator field, `length`) is a list of `{ "code", "message" }` instead of messages, so a client can choose copy by reason (`common_password`, `length`, `email`). The OpenAPI document gives `PUT /me/password` 403 for a wrong current password, as the server answers, instead of 401.

### Security
- CI and release workflows run only third-party actions pinned to a commit SHA, checkouts keep no credentials, and a `zizmor` job fails CI on a medium or high finding. The Trunk download is verified against a pinned SHA-256 per architecture in CI and in the edge image, base images and production compose services are pinned by digest, and two pushes of one release tag no longer run at once.
- Access tokens carry `typ: at+jwt` and `aud: rotaria-api`; a token for another audience or of another type is refused. Tokens issued before the change keep working until they expire. Every refused access token answers the same 401 message instead of naming the library error (`ExpiredSignature`, `InvalidSignature`).
- Signup and password change refuse a password from the 10,000 most common (SecLists, any letter case) with 400 `VALIDATION_FAILED`; the web forms refuse it before sending and say "Kata sandi itu terlalu umum dan mudah ditebak", from the server too.

## [0.1.1] — 2026-11-04

### Added
- `GET /progress/reading` lists every unfinished book, most recently read first (at most 100). The profile shelf shows them all with their progress next to downloads, says "Belum ada buku yang sedang kamu baca" to a reader who has only quotes, and invites browsing the catalog only when there are no books, downloads, or quotes.
- Curator desk: a dead letter names its book and can be dismissed for good (`DELETE /admin/dlq/{id}`), and the queue counter shows every dead letter in the stream, not the hundred on screen. An archived book can be published again ("Terbitkan lagi") when its ingestion had finished; one archived midway answers 409 and asks for a new upload. A book shows as Processing while its job runs and returns to Draft if the job fails for good. After a queued upload the form clears and the manuscript list reloads.

### Changed
- A heartbeat inside the per-reader window (a second open tab) answers 200 with `credited: false` and the standing unchanged, instead of 429, so reading in two tabs logs no errors. The window is 55 s against the reader's 60 s beat, so a beat that lands early after a slow one is still credited.
- `POST /activity/heartbeat` takes an optional `utc_offset_minutes` (-720 to 840, the device clock's minutes east of UTC) and `GET /me/streak` takes it as a query parameter; a streak day and today's reading minutes follow that local day instead of UTC. The web app sends the device's offset; omitting it keeps UTC. An offset outside the range answers 400 `VALIDATION_FAILED`.
- The web bundle loads faster on phones: release builds minify HTML, CSS, and the wasm-bindgen glue (CSS 72 to 52 KB, glue 80 to 47 KB), the edge image's bundle (`make build-web-edge`) carries brotli 11 and gzip copies Caddy sends as they are (the WASM travels 473 KB instead of 658 KB), the phone picks rail keeps its height while loading (home CLS 0.29 to 0.07), the off-screen hero plate loads lazily, and a build against an API on another origin preconnects to it. Mobile Lighthouse on home: score 52 to 71, LCP 5.7 to 4.9 s.
- The home page paints its heading before the WASM arrives: `index.html` carries a static copy of the phone header and greeting heading in the app's own classes, in the language the app will pick, shown once its two EB Garamond faces (preloaded on `/` only) are in, and removed when the app mounts. A reader with a book to resume does not get it, so the fresh-visitor greeting never stands in for theirs. Mobile Lighthouse on home: LCP 4.5 to 2.8 s, first paint 4.5 to 1.6 s, score 74 to 75; book and reader unchanged. Total blocking time rises from 31 to 690 ms because the WASM start now falls after the first paint.
- `POST /quotes/save` and `save-batch` keep a quote only if its text is in the chapter it names (400 `VALIDATION_FAILED`, or a `rejected` batch item, otherwise), so a share card can no longer credit a book with words it does not contain.
- `GET /admin/dlq` returns `{ total, entries }`; each entry adds `book_title`. A refused status change reads "A book that is archived cannot become draft".
- `GET /quotes` returns one page, newest first: `limit` (default 50, at most 100) and `cursor` (the id of the last quote of the previous page). The profile loads further pages with "Muat lebih banyak".
- `POST /auth/signup` answers with a `registration_id`, and `POST /auth/verify-otp` requires it next to the email and code. A signup no longer writes an account row; the account is created when the code comes back.
- `/health` and the OpenAPI document report the workspace version instead of a fixed `0.1.0`.

### Security
- Rust dependencies patched: rustls 0.23.46, rustls-webpki 0.103.16, webpki-roots 1.0.11, tokio 1.54.1, ctutils 0.4.8. The S3 client drops its legacy connector (rustls 0.21, hyper 0.14, h2 0.3) and SigV4a, so the server carries one TLS stack. `cargo audit` leaves only rsa, which is in the lockfile through sqlx-mysql but compiled into nothing, plus unmaintained (paste, proc-macro-error2) and yanked (yoke-derive 0.8.3) notices.
- EPUB covers decode only as JPEG, PNG, WebP or GIF with Pillow 13 (39 advisories against 12.3 closed), at most 40 megapixels: a 13000x13000 bomb is refused at its header within 200 MB instead of taking 1.77 GB. A cover that does not decode is dropped and the book publishes without one; raw cover bytes are never stored, and `GET /covers/{file}` takes its content type from the file extension, so nothing is ever served as SVG.
- One upload has a bounded cost: a spine naming one document many times yields one chapter, a book may have at most 2,000 chapters, 32 MB of text and 8,000 embedded passages, and an archive declaring more than 5,000 entries is refused before its directory is read (400,000 entries used to cost 469 MB just to refuse). Such an upload fails at once with its reason on the curator desk, without retries. Production compose caps the worker at 768 MB.
- One account cannot grow storage without bound: writes on `/me`, `/progress` and `/quotes` are capped at 120 per minute per account (429 with `Retry-After`), and an account keeps at most 5,000 quotes (409 `QUOTA_EXCEEDED`, shown in the reader as "Rak kutipanmu sudah penuh").
- A login or signup flood can no longer exhaust API memory: at most `ARGON2_MAX_CONCURRENCY` Argon2 operations (19 MiB each, default the core count up to 8) run at once, and a request that waits 2 s for a slot answers 503 with `Retry-After`. The server image fixes glibc's mmap threshold so each Argon2 buffer is returned on free; 100 concurrent logins peak at 189 MB instead of 1.3 GB.
- Rate limits count an IPv6 client by its /64, so rotating addresses inside one block no longer resets the auth, signup, login and AI limits; an IPv4-mapped address counts as its IPv4. Two ceilings across every client cap what abuse can cost: `OTP_HOURLY_BUDGET` (signup answers 503 past it) and `AI_DAILY_BUDGET` (semantic search answers 429 `AI_RATE_LIMITED` past it; guests together get a fifth of it, so they cannot take search from signed-in readers). Mail that was never sent and logins whose password was never checked are given back. Production refuses to boot with either at 0, or without `TRUST_PROXY_HEADERS=true` and `TRUSTED_IP_HEADER`.
- Signup cannot hold or hijack someone else's address: registrations for one address live side by side, each holding its own password, and a code only activates the registration it was mailed for. Codes mailed to one address are capped at 3 per hour and 10 per day (the 60-second cooldown is gone), and guesses are capped at 10 per address per day across every code, so asking for a new code never buys more attempts.
- Login answers unknown, unverified and wrong-password attempts in the same time (Argon2 always runs), and counts attempts atomically before Argon2, so twenty parallel guesses evaluate five. Signing a device out, or logging out, revokes every access token that device was given, not only the newest: access tokens carry a session id kept across refreshes. Refresh rotation and family revocation are single Redis scripts.
- Public routes no longer tell an unpublished book from a missing one: a draft, an archived book and a random id answer the same 404, and the cover of a draft or archived book is 404 too. Signup for an address that already has an account answers 201 like any other and mails the owner a note instead of a code, so signup no longer reveals who is registered.

### Fixed
- On a fresh install the first minute of reading no longer answers 500: the master badges were seeded only when someone listed them, so a reader who earned First Step before that broke a foreign key. The badges are now seeded before any award.
- Development tools: `make dev-web` reloads the page on a change again, without a WebSocket error every five seconds (the inline-script hook moved Trunk 0.22's live-reload script out of the page before its address was filled in). The API binds `APP_HOST` instead of always every interface, and `.env.example` sets it to `127.0.0.1`, so the dev API stays off the local network (the Android emulator still reaches it at 10.0.2.2; the server image keeps `0.0.0.0`); an `APP_HOST` that is not an IP address stops the boot with its reason. The dev Swagger UI is 5.34.1 with DOMPurify 3.4.17 (was 5.32.6 with 3.4.0), and utoipa-swagger-ui 10.0.2 builds with zip 9.3.
- A badge's XP is added to the total when the badge unlocks, exactly once: First Step's "+50 XP" now shows in the profile total. "Keluar dari semua perangkat", "Keluarkan perangkat lain" and the curator's archive button disarm 4 s after the first tap or at a tap elsewhere. The device list reloads after a password change that signs other devices out.
- Dates read on the reader's clock: a quote saved at 06:56 WIB on 3 November shows "3 Nov 2026", not the 2nd, and "Terakhir aktif" and "Pembaca sejak" no longer fall a day behind. Reading at 23:00 and again at 06:30 WIB counts as two streak days.
- Offline after a single visit: the service worker precaches, on install, every static file the app shell names, the house fonts (latin subsets), and the reader-facing illustrations, so a reader who saves a book and goes offline straight away gets the full app, its typefaces, and its art instead of an empty page or alt text. Offline, the home page and a guest's "Rak" list the books saved on the device ("Tersimpan di perangkat ini"). The worker reads the minified shell's unquoted attributes, which would otherwise have pruned every cached build file after each visit.
- Accessibility and search basics: a book's chapter text, synopsis, and quote passages carry the book's language, so a screen reader reads an Indonesian book as Indonesian in the English interface and hyphenation follows it; every route has its own document title in both languages ("Judul Buku — Rotaria"); the reader's chapter button is named by what it shows; the "Aa" panel takes focus when it opens and gives it back to "Aa" on Escape; a missing page keeps the header, `main`, and navigation. The site serves `robots.txt`, and the edge falls back to the app shell only for paths without an extension, so a missing file (`/missing.wasm`, `/sitemap.xml`) answers 404 instead of the shell.
- "Bagikan buku" and "Bagikan kartu" work in browsers without the Web Share API (desktop Chromium on Linux, Firefox): they copy the link or the quote and say so, instead of failing with a page error. A copied quote says "Kutipan disalin", not "Tersimpan".
- Error messages read in the reader's language: in Indonesian every refusal is "kamu" copy chosen by the error code and the field the server refused (a short new password, a wrong email, a file that is not an EPUB, an expired session), never the server's English text; a rate limit says how long to wait ("coba lagi dalam 15 menit"). The 429 message now ends with that wait. Error codes are listed once in `shared::error_code`, and a unit test holds a dictionary entry for each in both languages.
- Every API error is the JSON envelope, including input axum refuses before a handler runs (an unparsable id or `limit`, a body without its content type, malformed JSON, a missing field, a wrong method), which used to answer `text/plain`. Text with a NUL byte answers 400 instead of 500. The OpenAPI document lists 400, 415, 422, 429, 500, and 401 where a token is required on every operation, carries the validators' length and range bounds, wraps `GET /me/sessions` and `GET /quotes` in the envelope, and marks the logout token optional. `limit` on `GET /books` and `GET /books/search` is a 64-bit integer, clamped as before.
- Catalog search finds words that only a book's description holds: the query is parsed with the same `simple` config as the index instead of the database's English stemmer, which turned "running stories" into terms the index never holds.
- "Lihat seluruh katalog" reaches every published book exactly once: books without a publication year (every curator upload) now come after the dated ones instead of being skipped by the cursor, so a later page no longer comes back empty. The catalog page reads its index without a sort.
- "Buka halaman" on a quote search hit opens the reader on the paragraph the passage starts in, lit as an in-book hit is, instead of the chapter's start or the saved place. Quote search results carry `cfi_range` (`p-N`); `make backfill-paragraphs` anchors books ingested before.
- Project Gutenberg books ingest without the Gutenberg header and license: the license no longer becomes a chapter with its own insight cards and recap. Text a book keeps outside any paragraph is wrapped in one, so it has a `p-N` anchor and in-book search finds it.
- In-book search reads a paragraph index instead of splitting every chapter's HTML per request: a search with no hit on an 8 MB book answers in about 8 ms (was 520 ms of database time), a phrase broken across source lines and text with `&` are found, and online and offline search return the same paragraphs. Capital `İ` and a final sigma now match. The endpoint has its own limit per client (`BOOK_SEARCH_RATE_LIMIT_PER_MINUTE`, 30 in production compose), and every API statement is cancelled after `DATABASE_STATEMENT_TIMEOUT_MS` (5,000). After migrating, run `make backfill-paragraphs` (production: `make prod-backfill-paragraphs`, before the new server takes traffic); until then in-book search finds nothing in books ingested earlier.
- Curator uploads survive an expired session: the upload refreshes the token once and sends the file again instead of showing "Invalid or expired access token". A file over 50 MB is refused in the browser before it is sent, and the API answers 413 `PAYLOAD_TOO_LARGE` in the JSON envelope instead of "Error parsing multipart/form-data request". A title or language left blank is read from the EPUB (`dc:title`, `dc:language`) instead of being made from the file name and set to English.
- A broken upload fails in under a second with its reason on the curator desk and in the dead-letter queue (a plain zip, a missing `container.xml`, a truncated file, an object gone from storage); it used to take 44 minutes of retries. A book that kills the worker three times is dead-lettered instead of reclaimed forever, a retry waiting its turn shows why the last attempt failed, and an old backlog no longer delays newer jobs. `GET /admin/jobs/{id}` adds `attempts`.
- Archiving a book while it ingests answers at once: the worker commits metadata and cover before the long embedding and summary phase instead of holding the book row to the end, and a status change waits at most 2 seconds for the row before answering 409. The book stays archived.
- A chapter with a void `<embed>` or an unclosed `<iframe>`/`<object>` keeps every paragraph after it; it used to lose the rest of the chapter. Every job hash the worker writes expires after 7 days, and the server no longer has a panic path when the embedding fallback starts.
- Changing the password with a wrong current password says so in the form (403 `FORBIDDEN`) and leaves the device signed in; it used to answer 401, so the client refreshed, sent the change twice, and signed the reader out. The client ends a session only when the refresh itself is refused, and requests waiting on that refresh are dropped instead of resent.
- Reader: a chapter that fails to load no longer moves the chapter number, the URL or the saved position; the reader stays on the chapter on screen and says "Bab ini belum bisa dimuat", and a book that never loaded cannot reach the finale. Progress queued while the API was unreachable goes out when the app starts signed in.
- Queued progress belongs to the account that wrote it: signing out (or a refused session) drops that account's unsent writes, and a drain sends only the signed-in account's writes, so a shared device never moves one reader's position into another's shelf.
- Reader: resizing the window or rotating the phone keeps the paragraph being read on screen; the position is held as a paragraph and the share of it already read, applied once the new column width is laid out, instead of drifting back about a page per change.

## [0.1.0] — 2026-11-03

First release: the reader, the curator desk, the ingestion worker, and the deployment stack as they stand on this date. A 0.y version is initial development under semantic versioning; the public launch waits on the launch gate (staging domain, live email, trademark search).

### Added
- Tauri 2 app shell (`apps/tauri`) for Android and desktop around the same web bundle: the API base is injected at run time, no service worker inside the app, `rotaria://book/<id>` links open the book (also on a cold start), and Android keeps the page between the system bars. Verified on an Android 16 emulator: catalog from the host API, a book opened by deep link, page turns by swipe, and reading a saved book in airplane mode. `make app-dev`, `app-build`, `app-test`, `app-android-dev`, `app-android-build`.

The last page of a chapter says so instead of "~0 minutes left".

### Security
- Deploy surface trimmed: dev compose ports bind to `127.0.0.1`; `Caddyfile.prod` drops the `Server` banner on API and error responses; production refuses `SMTP_SECURITY=none`; server and worker images run as uid 10001 (the server image gains the `wget` its healthcheck calls); ingestion and dead-letter streams are capped at about 10000 entries.
- Rate limits cannot be gamed or stuck: every counter is `INCR` plus `EXPIRE NX` in one transaction (auth, AI, public, signup, lockouts, OTP); a revoked token counts in the guest AI bucket; production refuses to boot with a public cap but no proxy trust, and configuration errors exit with a message instead of a panic.
- Account takeover and abuse paths closed: a signup with a different password cannot replace the password of a registration whose code is pending (429 until it expires); OTP attempts are counted atomically, so parallel guesses cannot pass the three-attempt limit; the refresh grace window refuses a successor killed by revoke-all; password change revokes sessions before writing the new hash; emails are trimmed and lowercased, and a concurrent duplicate signup answers 409; progress writes and the active shelf ignore draft and archived books; only the EPUB upload route accepts bodies above 2 MB.
- Client address comes from one header: with `TRUST_PROXY_HEADERS=true` only `TRUSTED_IP_HEADER` (default `x-forwarded-for`) is read; `Caddyfile.prod` strips the other address headers. The default JWT secret is refused whenever proxy headers are trusted.
- Worker sanitizer re-escapes decoded character references, so markup hidden in entities stays text.
- Draft and archived books answer 404 on chapter, insight, and offline-bundle routes.
- SMTP through `lettre` with STARTTLS (`SMTP_SECURITY=starttls|none`); Gemini key sent in `x-goog-api-key`; connection strings, recipients, and OTPs masked in logs.
